# Expo SDK 58 upgrade

## Scope

- Expo 54 → 58.0.23, React Native 0.81.5 → 0.88.1, React 19.1 → 19.3, TypeScript 6.0.3.
- Align Expo/native dependencies with the SDK 58 compatibility matrix and regenerate the npm lockfile.
- Update calendars and chart-kit; retain Victory Native 41.26 because Victory 43 requires a different Skia package/version than Expo's supported Skia 2.14. Babel 7 and ESLint 9 remain compatible toolchain majors.
- Add the missing Reanimated Worklets dependency and a development client.
- Replace the legacy keyboard-aware-scroll-view with keyboard-controller on all three editing screens, with a root KeyboardProvider and GestureHandlerRootView.
- Use Expo Router's navigation context exports (theme, tab height, tab button) so they match Router's navigators.
- Update component prop/ref types for React Native's strict public API and resolve existing typecheck errors without weakening TypeScript strict mode.
- Use the Expo SVG transformer and convert the JPEG-disguised-as-PNG app icon to real PNG.
- Regenerate the checked-in Android project using SDK 58 prebuild, including Gradle wrapper, native entry point and Sentry Gradle integration. Preserve app identifiers, database name, EAS project and app version 1.1.3.

## Development

Use Node 24 LTS (`nvm use`) and `npm ci`. Copy `.env.example` to `.env.local` and set `EXPO_PUBLIC_SENTRY_DSN` to your Sentry project DSN; also configure it in each EAS build/update environment. The embedded DSN was removed from source; reporting is disabled until this value is configured. Run `npm run ios` on macOS with Xcode or `npm run android` with an Android SDK/JDK. The development EAS profile now has expo-dev-client available. Existing SDK 54 development binaries must be rebuilt.

The Android project remains checked in. EAS does not automatically reapply app.json plugins to an existing Android directory: run `npx expo prebuild --platform android --clean --no-install` after native config/plugin changes, inspect the diff, and verify versionName before committing. Keep native customizations in app config/plugins. iOS is generated by EAS/prebuild because no ios directory is tracked.

## Web bundling follow-up

Lottie 7.5 requires the optional peer `@lottiefiles/dotlottie-react` for web/server bundles. It is now an explicit dependency. Run `npm ci`, restart with `npx expo start --web --clear`, and use `npm run export:web` to check static export.

Metro includes SQLite's `.wasm` assets and sets `Cross-Origin-Embedder-Policy: credentialless` and `Cross-Origin-Opener-Policy: same-origin` in development. Configure those same response headers on any production web host; Metro middleware does not configure exported hosting. See [Expo SQLite web setup](https://docs.expo.dev/versions/latest/sdk/sqlite/#web-setup). Browser runtime behavior still needs a smoke test.

The web root defers local-storage providers and workout screens until client hydration. Static rendering must not access browser storage or render charts before their data providers are initialized. Native rendering is unaffected by this web-only guard.

## Skia web initialization follow-up

Skia v2 captures CanvasKit when its JavaScript modules are evaluated. Importing Victory charts before `LoadSkiaWeb` resolves leaves that captured engine undefined and can fail at `XYWHRect`.

`index.web.ts` now loads CanvasKit before dynamically importing Expo Router's entry point (and therefore its chart routes). Native uses the standard Router entry through `index.ts`. The `postinstall` script runs Skia's `setup-skia-web` to copy the installed, matching CanvasKit WASM into `public/canvaskit.wasm`; it is generated and not checked in. Use `npm ci` normally, or `npm run postinstall` if install scripts were skipped. Both Metro and web exports serve that public file locally, without a CDN. If graphics initialization fails, the startup page displays a reload message rather than an unhandled rejection.

Reference: [Skia v2 web loading](https://wcandillon.github.io/react-native-skia/v2/docs/getting-started/web/).
